# Sweepr native mobile apps (iOS + Android via SKIP)

Two genuinely-native mobile apps that share one Swift codebase and transpile to
Kotlin/Jetpack Compose for Android using [SKIP](https://skip.tools). **Not** web
wrappers — native SwiftUI on iOS, native Compose on Android, from the same Swift
source.

## The three modules

```
apps/ios/
├── SweeprKit/                 shared Swift package (models, networking, auth, theme, UI)
│   ├── Package.swift          SKIP deps (skip, skip-ui, skip-foundation, skip-model)
│   └── Sources/SweeprKit/
│       ├── Models/            Booking, Address, Cleaner, Quote, Membership,
│       │                      SmartEntryAccess, DayOfServiceStatus, Job, Money,
│       │                      BookingStatus (mirrors lib/statusMachine.ts) + MockData
│       ├── Networking/        SweeprAPI (async/await URLSession, Bearer auth)
│       ├── Auth/              AuthTokenProvider protocol (Clerk bridge point)
│       ├── Theme/             SweeprTheme design tokens (seafoam / warm graphite)
│       ├── UI/                SweeprButton, SweeprCard, SweeprBadge, SkeletonBlock
│       └── Skip/skip.yml      SKIP transpile marker
│
├── Sweepr/                    CUSTOMER app — "Sweepr" (com.getsweepr.customer)
│   ├── Package.swift          depends on ../SweeprKit
│   ├── Skip.env               bundle id, version, Clerk pk, API base
│   ├── Darwin/Info.plist      iOS app metadata + usage strings
│   └── Sources/Sweepr/
│       ├── SweeprApp.swift    @main
│       ├── RootView.swift     TabView: Home · Book · Bookings · Account
│       ├── Support/           AppEnvironment (SweeprAPI + token provider)
│       ├── Screens/           Home, Bookings, BookingDetail, BookFlow (stub),
│       │                      LiveTracking (native map), Account
│       └── Skip/skip.yml
│
└── CleanWithSweepr/           CLEANER app — "Clean with Sweepr" (com.getsweepr.cleaner)
    ├── Package.swift          depends on ../SweeprKit
    ├── Skip.env
    ├── Darwin/Info.plist
    └── Sources/CleanWithSweepr/
        ├── CleanWithSweeprApp.swift   @main
        ├── RootView.swift     TabView: Jobs · Route · Earnings · Account
        ├── Support/           AppEnvironment
        └── Screens/           Jobs, JobDetail (day-of-service: check-in +
                               Smart Entry reveal-unlock), Route (map),
                               Earnings, Account
```

Both apps depend on `SweeprKit` via a local SwiftPM path dependency, so models,
the API client, auth, the theme, and shared components are written **once**.

## How the dual-native SKIP approach works

- Each module is a **Swift Package Manager** package. A `Skip/skip.yml` marker in
  each source target tells the `skipstone` build-tool plugin to transpile that
  Swift into a Kotlin/Gradle module.
- The iOS app targets live in an Xcode project under each app's `Darwin/` folder
  (see "Finishing setup" — the `.xcodeproj` is generated by `skip init` and then
  committed). `skip export` produces the Android app from the same Swift.
- We stay inside the SwiftUI/Foundation subset SkipUI/SkipFoundation/SkipModel
  support. Platform APIs that differ (MapKit ↔ maps-compose) are declared in
  `skip.yml` Gradle blocks and used through the SkipUI-supported surface.

## Design system

`SweeprKit/Theme/SweeprTheme.swift` ports `packages/config/tailwind.ts`:
seafoam brand (`#0f766e` / `#14b8a6`), charcoal `#1c1a17`, and the deliberate
"warm graphite" (no blue) dark mode. Radii, spacing, and fonts are tokenized.
`Color(light:dark:)` gives theme-aware colors that map to Compose's dark-theme
check on Android.

## Backend integration

`SweeprAPI` (actor) talks to the Hono API at `https://api.getsweepr.com` with
async/await `URLSession` and a `Bearer` token from an injected
`AuthTokenProvider`. Wired endpoints: `GET /bookings`, `GET /bookings/:id`,
`GET /membership`, `GET /cleaner-dashboard/jobs`, `GET /day-of-service/:id`,
`GET /cleaner-dashboard/earnings`. Money crosses the wire as **integer cents**
(`Money`) exactly like the DB; the client never computes totals. Every screen
falls back to `SweeprMock` data when the network/Clerk session is unavailable, so
the UI is coherent in previews and offline.

### Auth (Clerk) — the one TODO to finish

`AuthTokenProvider` is a protocol so SweeprKit stays SDK-free and transpilable.
Each app currently injects `AnonymousTokenProvider`. To go live, add a
`ClerkTokenProvider` in each app target that returns
`Clerk.shared.session?.getToken()` (primary application, `clerk.getsweepr.com`).
Only the publishable key (`pk_…`, in `Skip.env`) ever lives in source.

## Build iOS (needs a Mac + Xcode + the skip toolchain)

```bash
brew install skiptools/skip/skip     # one-time: installs the skip CLI
skip checkup                         # verifies Xcode, Android SDK, Gradle, JDK

# Open either app in Xcode and run on the iOS simulator:
cd apps/ios/Sweepr        # or apps/ios/CleanWithSweepr
xed .                     # opens Package.swift / the Darwin xcodeproj
# ⌘R the app scheme
```

## Generate / run Android (transpiled)

```bash
cd apps/ios/Sweepr        # or apps/ios/CleanWithSweepr
skip export               # transpiles Swift → Kotlin/Compose Gradle project
# then run the generated Android app:
skip launch --android     # builds + installs to a connected device/emulator
```

`skip verify` transpiles + builds both platforms and is the CI gate.

## Finishing setup (what still needs a real Mac/Xcode/skip toolchain)

This skeleton was hand-authored to the canonical SKIP layout in an environment
without Xcode or the `skip` CLI. On a Mac, a developer runs once per app to
generate the Xcode project + Android Gradle scaffolding SKIP expects:

```bash
brew install skiptools/skip/skip
cd apps/ios
# Regenerate the app project scaffolds around the existing Sources/ (skip will
# pick up the committed Package.swift, Skip.env, Darwin/Info.plist and skip.yml):
skip init --appid com.getsweepr.customer  Sweepr Sweepr
skip init --appid com.getsweepr.cleaner   CleanWithSweepr CleanWithSweepr
```

Then pin the SKIP package versions to whatever `skip` reports (`skip verify`),
drop `Sweepr-logo.png` into `SweeprKit/Sources/SweeprKit/Resources/`, and add the
`ClerkTokenProvider`. After that, `skip export` / `skip launch --android`
produce the Android apps and Xcode runs the iOS apps.

## Not wired into pnpm/Turbo

These are a separate native toolchain (SwiftPM + Gradle) and are intentionally
self-contained under `apps/ios/`. They are **not** part of the pnpm workspace or
Turbo build, and they don't touch the web apps.
